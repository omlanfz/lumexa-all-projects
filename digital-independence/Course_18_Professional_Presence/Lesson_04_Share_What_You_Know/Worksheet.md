## Part 3: Filled Example — Jordan R.

**1. What I was doing:** This week I built a simple to-do list app where you can add and check off tasks.

**2. What I learned or noticed:** It worked great until I deleted every task and the app crashed with a blank error screen. I learned that I had only tested my app with tasks already in the list, so my code assumed there would always be at least one item. The fix was one `if` statement checking whether the list was empty before displaying it.

**3. Why it might help someone else:** If you're building anything with a list — tasks, messages, search results — try emptying it out completely before you call it done.

**4. Hook:** Testing your app's "empty state" actually matters.

**5. Takeaway:** The "nothing here" case is easy to forget and easy to break — always test it.

**6. Assembled draft:**

> **Testing your app's "empty state" actually matters**
>
> This week I built a simple to-do list app where you can add and check off tasks. It worked great — until I deleted every task and the app crashed with a blank error screen.
>
> I learned that I had only tested my app with tasks already in the list, so I never noticed that my code assumed there would always be at least one item. The fix was one `if` statement checking whether the list was empty before trying to display it.
>
> If you're building anything with a list — tasks, messages, search results — try emptying it out completely before you call it done. The "nothing here" case is easy to forget and easy to break.

**Self-check for Jordan's draft:** All six checks pass — concrete detail (the empty-list crash and the `if` statement fix), no inflated language, honest and answerable claims, all three formula parts present, appropriate length, and a specific (not generic) hook.
