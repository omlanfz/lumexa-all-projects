## Discovery Notes
Priya needs a simple, low-maintenance webpage. Events matter most to visitors. She is not
technical. No budget. Two-week timeline.

## Project Requirements
Must-haves: About, Events (prominent), Contact link. Nice-to-have: photo gallery (declined —
kept out of scope to hit the 2-week timeline). Constraints: $0 budget, low client tech skill,
2 weeks.

## Proposal (as submitted)
See `Proposal_Template.md`'s filled example above — this is the actual proposal Jordan sent.

## Pricing & Scope
6 estimated hours × $15 practice rate = $90 (simulated figure). Scope boundary: 1-page site
with About/Events/Contact, deployed live; does not include ongoing updates after handoff.

## Delivered Site (structure)
A single HTML page reusing the Course 16 portfolio CSS approach: Hero (club name + tagline),
Events section (moved to top per revision request), About section, Contact section with a
mailto link. Deployed via GitHub + Vercel per Course 16 Lesson 7 skills.

## Revision Handling
Moved Events section directly under the intro per client feedback. Documented as an in-scope
layout change, not scope creep, since no new feature was added.

## Handoff Message (as sent)
"Hi Priya — the Career Compass Club page is live at [link]. It includes your About section,
the Events list right after the intro as requested, and a contact link for interested
students. To update an event, just open the `events.txt` file I included and add a new line —
instructions are in the README I attached. Let me know if anything needs adjusting!"

## Why This Is Proficient
Discovery notes directly shaped the proposal; the scope boundary was explicit and held firm
during the revision; the revision was correctly identified as in-scope; the handoff included
plain-language instructions matching the client's stated non-technical constraint.
